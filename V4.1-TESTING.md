# v4.1 — Mesocycle lifecycle

## What changes

- Opening Advanced Guided Trainer no longer creates or starts a cycle.
- Start is explicit, with a start/deload/review date preview and confirmation.
- Cycle status stays visible before, during, and after training. Saved sessions identify their cycle, week, and phase in history and workout details.
- The cycle panel lists only explicitly linked Advanced Guided workouts. Earlier manual workouts, including earlier workouts named Push A, are not cycle members. Existing general recovery and Coach history calculations are unchanged.
- Review prepares next-cycle settings without starting the next clock.
- Start-date correction uses the existing cycle's first completed week-one accumulation workout. It never rewrites sets, workout dates, plans, or settings snapshots. A dated audit records corrections and compatible undo operations.

## Deployment

1. Export a profile backup before deploying; retain a recoverable database/volume backup as well.
2. Publish `v4.1-mesocycle-lifecycle` through Visual Studio.
3. Deploy this branch to the Railway service using the existing persistent database volume. Publishing a branch alone does not guarantee the live service deploys it; check the service's selected source branch.
4. Refresh the browser after deployment. Sign in again if the server restart expired your token.

The startup migration adds the explicit cycle relation and date-change audit. Valid existing Advanced Guided plan links are copied into that relation; manual history is never inferred into a cycle from its date, template, or name. Used legacy cycles retain their ID, start, and settings. Empty legacy auto-starts become awaiting-start records, without being deleted. Unresolved Advanced history prevents automatic retirement.

## Your existing Push A

1. Open Advanced Guided Trainer. Verify exactly one completed workout is linked: the latest Advanced Guided Push A. Earlier manual workouts must have no cycle badge.
2. Expand **Start-date correction**. If eligible, select **Use first workout date**.
3. Verify the confirmation shows Push A's saved calendar date and the revised deload/review dates before confirming. This corrects the existing cycle; do not start a replacement cycle.
4. Verify the cycle ID remains the same, the start is now Push A's date, and its saved week-one plan and logged sets are unchanged.
5. Undo is available only when restoring the previous date would keep every linked workout's saved week and phase compatible. An active workout blocks date changes.

## Fresh-cycle and workout checks

- A fresh/unused cycle remains awaiting-start when you open or refresh the trainer.
- Save settings, verify the preview, then start explicitly. Repeated start requests reuse the active cycle.
- Starting an Advanced workout attaches it to the active cycle and freezes its week/phase. You cannot silently move an active plan into another cycle or week.
- Finish a workout: the completion screen confirms its saved cycle/week/phase; the cycle list and history update.
- Missed workouts do not pause calendar weeks. Week boundaries are seven civil calendar days from the cycle start, including across daylight-saving transitions.
- Review is available after accumulation and deload and while no workout is active. Preparing the next mesocycle returns to awaiting-start.

## Verification

Run `npm run check`, `npm test`, and `npm run build` in a compatible Node environment. The test suite includes an old-schema upgrade, manual-history exclusion, authenticated HTTP lifecycle/linkage, first-workout alignment, ownership/stale-date guards, active-session and later-history conflicts, guarded undo, and unchanged saved workouts/sets.

No production workout or cycle date is changed by the implementation work itself. The alignment is a separate confirmed action in the deployed UI.
